# CSV pipeline examples

One runnable example per CSV use case. Each `*.flow.yaml` is a complete pipeline you can run with:

```bash
export SQLFlowSinkConStr="Server=localhost,1433;Database=TestDB;User ID=...;Password=...;TrustServerCertificate=True"
dotnet run --project src/SqlFlow.Cli -- run samples/csv/csv-basic.flow.yaml
```

`plan` first to see the exact SQL without touching the database:

```bash
dotnet run --project src/SqlFlow.Cli -- plan samples/csv/csv-basic.flow.yaml
```

These same files are executed against a sink database by the integration test
`SampleFlowIntegrationTests`, so the examples are guaranteed to work.

| Example | Attribute it demonstrates |
|---|---|
| `csv-basic` | comma-delimited with header (the defaults) |
| `csv-semicolon` | `delimiter: ";"` |
| `csv-pipe` | `delimiter: "\|"` |
| `csv-tab` | `delimiter: "\t"` |
| `csv-fixed-width` | `columnWidths` (no delimiter) |
| `csv-no-header` | `header: false` -> columns named `Column1..N` |
| `csv-quoted` | text qualifier; delimiter/newline inside a quoted field |
| `csv-escape-character` | `escapeCharacter` for a qualifier inside a field |
| `csv-comment-lines` | `commentCharacter` skips comment lines |
| `csv-skip-start-rows` | `skipStartingDataRows` drops a leading preamble |
| `csv-skip-end-rows` | `skipEndingDataRows` drops a trailing footer |
| `csv-trim` | `trim` strips surrounding whitespace |
| `csv-strip-control-chars` | `stripControlChars` removes control characters |
| `csv-encoding-utf16` | `srcEncoding: Unicode` for a non-UTF-8 file |
| `csv-max-rows` | `maxRows` caps how many rows load |
| `csv-include-line-number` | `includeFileLineNumber` adds a line-number column |
| `csv-show-full-path` | `showPathWithFileName` stores the full path |
| `csv-no-system-columns` | turn off the injected provenance columns |
| `csv-custom-default-type` | `schema.defaultColumnType` overrides the raw column type |
| `csv-folder-union` | load a folder; union columns across files |
| `csv-subdirectories` | `searchSubDirectories` recurses into sub-folders |
| `csv-path-mask` | `srcPathMask` regex over the full path (name and/or folder) |
| `csv-init-file-date` | `initFromFileDate` / `initToFileDate` bound files by modified date |
| `csv-file-date-partitions` | `fileDate.from: path` reads the date from Hive partitions and prunes out-of-window folders |
| `csv-truncate-load` | `load.mode: truncate-load` for a full refresh |
| `csv-desired-index` | `desiredIndexes` builds indexes on the new table |
| `csv-row-keys` | `includeHashKey` / `includeConcatKey` synthetic per-row keys |
| `csv-incremental` | `incremental` probes the target watermark; loads only new files |

## Editor IntelliSense

A JSON Schema at [`schemas/sqlflow.flow.schema.json`](../../schemas/sqlflow.flow.schema.json) drives
autocomplete, hover docs, and validation for `*.flow.yaml` files. The repo's `.vscode/settings.json`
already associates it (via the Red Hat YAML extension). For other editors, add a modeline to the top
of a file:

```yaml
# yaml-language-server: $schema=../../schemas/sqlflow.flow.schema.json
```

## Recommended attribute order

Author top-level keys in this logical order (source to target to behaviour):

```
name -> source -> target -> schema -> load -> incremental -> transform -> desiredIndexes -> preProcess -> postProcess
```

## Sample data

The `data/` folder holds the sample input files. `data/control-chars.csv` and `data/encoding-utf16.csv`
are generated by the test harness because their bytes cannot be shown in a plain text file.
